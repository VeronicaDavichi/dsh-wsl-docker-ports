## 1. 判据与现状

- **硬上限**：主包 ≤ **65,536 B**（§P2 的直接判据；限 = `MAIN_BUNDLE_LIMIT_BYTES`）。
- **现状**：`lib/client.js` = **144,149 B**、**无 chunk** ⇒ 超 **78,613 B = 2.20×**。
- **问题定性**：§P2 的 ①（不含 xterm）②（不含内联 React；`node_modules` 输入 0）**均绿** ⇒ **打包配置无缺陷**，是**纯体积**问题 ⇒ 处置手段只能是**切分**，不是修配置。
- **为什么不能靠「砍代码」**：越线的构成里 `src/client/**` 占 **80.2%**、首方非 client 源码占 **18.5%**，二者都是**功能所需**；归属上 `008 面` 25.1% + `009 面` 14.5% 且**初始 client 半第一天即越线** ⇒ 没有「谁的赘肉」可砍，只有**加载时机**可调。

## 4. 懒加载契约（`Phase 0` 门）

- **机制（据 §E14 的官方终端页逐字实证）**：chunk 自注册 `window.__ModuleLoader__.load({ id, chunk: "client.<name>.js", factory })`；取块 `(await require.async("./client.<name>.js")).<Export>`；**chunk 不进 `exports`**、`package.json` 的 `exports['./client']` 仍指主包。
- **主包保留**：`apply` / `inject` / tab 注册壳 + `require.async` 调用点（`react.lazy` 或等价）+ **降级态 UI 的最小依赖**。
- 🔴 **未验**：**0.2.0-rc.2 的 `require.async` 语义是否与 0.1.7-rc.2 一致**（§Z5 残留项）⇒ `Phase 0` **必须先真机验证「异步取块 → 执行 → 注册页」整链路**，**未验证不得进实现**。
- **切分粒度**：优先**一个 chunk**（渲染面 + 写路径内核同块）—— 两者在「打开页面」这一路径上**几乎同时需要**，拆两块只增加一次往返；若真机上出现「打开页面但不写」的常见路径，**再**评估把写路径内核独立成第二块（**不预设**）。

## 5. 失败 / 离线降级（REQ-BS-5）

- **必须**：取块失败 ⇒ 页面壳**保留**（tab 已在主包注册）+ 明确文案（「界面资源加载失败」+ 原因分类：网络 / 404 / 执行异常）+ **可重试**动作。
- **禁止**：**白屏**（整页空）、**静默**（把失败吞掉、假装没有内容）。
- **分类口径（沿用 008 的四态思路，但不改 008）**：`loading` / `ready` / `failed`（可重试）/ `offline`（提示网络）—— **只描述本 Spec 的降级态**，**不得**改动 008 的写结果四态与 401 文案（REQ-BS-4）。
- **可观测**：失败**必须**留下可查记录（控制台一条明确错误，非 `undefined` 抛出）。

## 7. 产物断言与变异哨兵

- **断言项**：① 主包字节 ≤ 65,536；② `require.async` 命中 ≥ 1；③ chunk 产物存在且被引用；④ 常驻 4 模块（`rows.ts` / `write-channel` / `write-token` / `settings-pipe`）的**标记字符串**仍在主包；⑤ 已切出模块的标记字符串**不在**主包。
- **标记字符串口径（待定）**：优先用**构建可保留**的稳定字面量（如注册键 / 路由字面量）；⚠️ 若 esbuild 压缩改名导致不可靠，改用**字节增量法**（切前 / 切后主包差值）—— **实现阶段定**，本轮不拍。

## 10. 决策与权衡

- **切分 vs 抬上限**：选**切分**。抬上限 = 改口径 SSoT（§P2 明写 ① ② 已绿 ⇒ 无正当理由），且「先塞后抬」被明示禁止。
- **一个 chunk vs 多 chunk**：**先一个**（打开页面即需二者），避免无谓往返；**不预设**第二块。
- **打断同步 import vs 不动 import**：**先不动**（不改产品语义）；仅当余量不足时另立设计变更。
- **UI 重构 vs 只切字节**：**只切字节**（非目标已写死；重构会污染「功能等价」验收）。
- **为什么不在 008 / 009 里做**：归属跨 003 / 008 / 009 三面，且**初始 client 半第一天即越线** ⇒ 放在任一子 Spec 都会把「已验收」与「新越门整改」混在一张表里。
